# Backend — Intelligent File Search

Локальный FastAPI-сервис для приёма файлов, извлечения признаков, построения
FAISS-индексов и семантического поиска. Компонент входит в коммерческий проект;
код опубликован только для технического ознакомления при рассмотрении резюме.
Условия использования приведены в [LICENSE](../../../LICENSE).

## Требования

- Python 3.10–3.12;
- не менее 4 ГБ свободной RAM;
- около 3 ГБ на веса моделей, загружаемые при первом запуске;
- CUDA-совместимый GPU опционален, при его отсутствии используется CPU.

## Запуск

```powershell
cd backend
py -3.10 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn main:app --host 0.0.0.0 --port 8000
```

```bash
cd backend
python3.10 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000
```

Сервис будет доступен на `http://localhost:8000`. При первом старте загрузка и
инициализация моделей могут занять 10–20 минут.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/index` | Запустить индексацию каталога, доступного backend |
| `POST` | `/upload-index` | Принять файлы от Android-клиента и запустить индексацию |
| `POST` | `/index-uploads` | Повторно проиндексировать последнюю загрузку |
| `GET` | `/status` | Получить прогресс фоновой индексации |
| `POST` | `/search` | Выполнить семантический поиск |
| `GET` | `/download` | Скачать найденную копию из upload-хранилища |
| `GET` | `/health` | Проверить доступность сервиса |

Пример:

```bash
curl -X POST http://localhost:8000/index \
  -H "Content-Type: application/json" \
  -d '{"path": "/absolute/path/to/files"}'

curl http://localhost:8000/status

curl -X POST http://localhost:8000/search \
  -H "Content-Type: application/json" \
  -d '{"query": "кот у окна", "file_type": "all", "top_k": 10}'
```

## Структура

```text
backend/
├── main.py              # API, lifespan и фоновые задачи
├── config.py            # пути, форматы, пороги и параметры индексации
├── models.py            # загрузка SigLIP, SBERT, EasyOCR и переводчика
├── indexer.py           # обход файлов и атомарная запись индексов
├── searcher.py          # поиск, агрегация и ранжирование
├── schemas.py           # Pydantic-контракты API
├── utils.py             # нормализация и разбиение текста
└── file_processors/
    ├── image_processor.py
    ├── video_processor.py
    ├── pdf_processor.py
    ├── docx_processor.py
    ├── text_processor.py
    ├── table_processor.py
    └── office_processor.py
```

Рабочие индексы и метаданные создаются в `storage/` и не коммитятся.

## Индексация и ранжирование

Для каждого файла формируется один или несколько признаков:

- SigLIP-вектор для изображений и усреднённых кадров видео;
- OCR-текст для изображений, сканов и графики внутри PDF;
- SBERT-векторы для текстовых чанков документов и таблиц;
- имя файла как запасной текстовый сигнал.

Визуальные и текстовые признаки хранятся раздельно из-за разной размерности.
При поиске backend берёт расширенный список кандидатов из обоих индексов,
объединяет их по `filepath`, применяет весовой score и возвращает top-K без
дублирования одного файла.

## Подключение Android-клиента

```bash
# Физическое устройство по USB
adb reverse tcp:8000 tcp:8000
# В клиенте: http://localhost:8000

# Android Emulator обращается к хосту по адресу
# http://10.0.2.2:8000
```

Клиент также умеет находить `/health` в локальной Wi-Fi подсети.

## Эксплуатационные ограничения

- сервис рассчитан на один процесс: каждый worker держал бы отдельную копию
  ML-моделей и индексов;
- CORS открыт, а аутентификация не реализована, поэтому API следует запускать
  только в доверенной локальной сети;
- Flat-индекс выполняет точный линейный поиск и подходит для локальных коллекций;
- повреждённые и зашифрованные PDF пропускаются с записью в лог;
- `.doc` не поддерживается, для Word используется `.docx`.
