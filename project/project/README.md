# Intelligent File Search

Система семантического поиска по локальным файлам: Android-клиент отвечает за
выбор и передачу данных, FastAPI-сервис — за извлечение признаков, построение
индексов и ранжирование результатов.

Этот каталог содержит обзорную версию коммерческого проекта. Исходный код
доступен только для проверки квалификации автора в рамках найма. Условия
использования приведены в корневом файле [LICENSE](../../LICENSE).

## Сценарий работы

1. Пользователь разрешает приложению доступ к файлам или выбирает их вручную.
2. Клиент отправляет файлы на backend пакетами.
3. Backend извлекает текст, OCR и визуальные признаки.
4. Текстовые и медиа-векторы сохраняются в отдельных FAISS-индексах.
5. Поисковый запрос кодируется в соответствующих пространствах, результаты
   объединяются по файлу и сортируются по итоговому score.
6. Найденный файл скачивается во временный каталог Android и открывается
   зарегистрированным приложением.

## Компоненты

```text
project/
├── backend/      # FastAPI, обработчики файлов, ML-модели, FAISS
├── mobile/       # Flutter-клиент для Android
└── experiment/   # проверка качества поиска и тестовые наборы
```

| Компонент | Стек |
|---|---|
| Backend | Python 3.10–3.12, FastAPI, PyTorch, SigLIP, SBERT, EasyOCR, FAISS |
| Mobile | Flutter 3.19+, Dart, Android SDK |
| Quality checks | Python, requests, Flickr8k, Precision@K |

## Локальный запуск

### Backend

```powershell
cd backend
py -3.10 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn main:app --host 0.0.0.0 --port 8000
```

При первом запуске будут загружены веса моделей. Подробности и примеры API —
в [backend/README.md](backend/README.md).

### Android-клиент

```powershell
cd mobile
flutter pub get
flutter run
```

Настройка подключения и Android-разрешений описана в
[mobile/README.md](mobile/README.md).

### Проверка качества поиска

```powershell
cd experiment
python build_real_dataset.py --out ./real_dataset --images 20
python run_experiment.py --server http://localhost:8000 `
  --dataset ./real_dataset --queries ./real_queries.json
```

Перед запуском оценки каталог нужно проиндексировать через `POST /index`.
Полный порядок действий — в [experiment/README.md](experiment/README.md).

## Технические решения

- Текстовые и визуальные векторы разделены: SBERT использует размерность 384,
  SigLIP — 768. Для них создаются независимые FAISS-индексы.
- Результаты двух индексов агрегируются по пути к файлу. Это позволяет
  совместить OCR, содержимое документа и визуальное сходство без дублей.
- Индексы записываются во временные файлы и заменяются атомарно, поэтому поиск
  не читает частично построенное состояние.
- Состояние фоновой индексации защищено блокировкой; второй параллельный запуск
  возвращает статус `busy`.
- Переводчик ru→en загружается только для русскоязычного медиа-запроса.
- В PDF обрабатываются текстовый слой, сканированные страницы и встроенные
  изображения, но мелкая декоративная графика пропускается.
- Android-клиент загружает файлы пакетами и может продолжать передачу через
  foreground service.

## Проверка качества

В репозитории есть два набора:

- детерминированный синтетический набор для регрессионных проверок;
- смешанный набор с реальными фотографиями Flickr8k и документами разных типов.

Скрипт `run_experiment.py` сравнивает семантический поиск с подстрочным поиском
по имени файла и формирует JSON-отчёт с результатами по каждому запросу.

## Ограничения текущей версии

- backend запускается на ПК; ML-модели не рассчитаны на память телефона;
- индексация на CPU занимает примерно 1–5 секунд на файл в зависимости от типа;
- поддерживается Android, сборка для iOS не подготовлена;
- зашифрованные и повреждённые PDF пропускаются;
- старый бинарный формат `.doc` не поддерживается;
- `IndexFlatIP` даёт точный поиск, но при сотнях тысяч векторов потребует замены
  на HNSW или IVF;
- локальный API не содержит аутентификации и не предназначен для публикации в
  открытом интернете.
