# Mobile — Flutter-клиент

Android-клиент коммерческой системы семантического поиска файлов. Публичная
копия предназначена только для технического ознакомления и подтверждения опыта
автора при рассмотрении резюме. Условия использования приведены в
[LICENSE](../../../LICENSE).

## Как работает клиент

1. Пользователь выдаёт доступ к общему хранилищу или выбирает файлы через
   системный picker.
2. Приложение находит поддерживаемые документы и медиафайлы.
3. Файлы отправляются на backend пакетами через `/upload-index`.
4. Длительная загрузка выполняется в Android foreground service.
5. Поисковые запросы уходят на `/search`.
6. Выбранный результат скачивается через `/download` во временный каталог и
   открывается установленным приложением.

Backend работает на ПК и не может читать Android-пути вида
`/storage/emulated/0/...`, поэтому перед индексацией клиент передаёт ему копии
файлов.

## Требования

- Flutter 3.19+;
- Android SDK и устройство либо эмулятор;
- запущенный backend из соседнего каталога;
- доступ к одной локальной сети или USB-подключение с `adb reverse`.

## Запуск

```bash
flutter pub get
flutter run
```

Если нативная Android-обвязка отсутствует в рабочей копии, её можно восстановить:

```bash
flutter create --platforms=android .
```

После восстановления нужно сохранить настройки проекта:

- `android.permission.INTERNET`;
- `android.permission.MANAGE_EXTERNAL_STORAGE`;
- `android:usesCleartextTraffic="true"` для локального HTTP-сервиса;
- `FileProvider` для `open_filex`;
- MethodChannel `intelligent_file_search/storage` в `MainActivity`.

## Подключение к backend

| Сценарий | URL |
|---|---|
| Android Emulator | `http://10.0.2.2:8000` |
| Физическое устройство с `adb reverse tcp:8000 tcp:8000` | `http://localhost:8000` |
| Телефон и ПК в одной Wi-Fi сети | `http://<IP_ПК>:8000` |

В Wi-Fi сети приложение сначала пытается автоматически найти backend по
эндпоинту `/health`. Адрес всегда можно изменить вручную в настройках.

## Доступ к файлам

`MANAGE_EXTERNAL_STORAGE` используется потому, что поиск по всей пользовательской
коллекции — основная функция приложения. Это чувствительное Android-разрешение:
перед публикацией в Google Play необходимо подтвердить соответствие политике
доступа ко всем файлам. Ручной выбор через системный picker остаётся вариантом
с минимальными разрешениями.

Сканер пропускает системные и служебные каталоги, фильтрует расширения и не
отправляет данные до подтверждения пользователя.

## Основные модули

```text
lib/
├── models/       # контракты статуса и результатов поиска
├── screens/      # поиск, индексация, загрузка и настройки
├── services/     # API, сканирование, discovery и foreground upload
├── widgets/      # карточки результатов
└── main.dart
```

## Ограничения

- клиент подготовлен только для Android;
- локальный HTTP допустим для доверенной сети, но production-сборке потребуется
  защищённый транспорт и аутентификация;
- release signing и данные публикации не входят в обзорную копию;
- скорость первой индексации зависит от сети, объёма файлов и мощности backend.
